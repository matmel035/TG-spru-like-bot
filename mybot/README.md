# Мой агент в Telegram

Свой персональный агент: Telegram-бот + LLM с вызовом инструментов + память в SQLite.
Всё на Python, всё правится руками — никакой магии, которую нельзя посмотреть.

## Быстрый старт

```bash
cd mybot
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env   # вписать токен и ключ
python bot.py
```

Токен бота — от @BotFather в Telegram. Ключ модели — в `.env` (подойдёт любой OpenAI-совместимый).

## Где что лежит

```
bot.py                 Telegram-обёртка: личка, группы, топики, реакция на упоминания
config.py              настройки из .env + чтение системного промпта
agent/system.md        ХАРАКТЕР АГЕНТА. Правится как обычный markdown, подхватывается при старте
agent/core.py          цикл: модель -> инструмент -> модель -> ответ
agent/tools.py         реестр инструментов (добавляешь функцию с @tool — она доступна модели)
agent/memory.py        SQLite: история диалогов + долговременные заметки
tests/test_agent.py    прогон без Telegram и без реального API (подставной LLM)
tests/test_group.py    проверка логики «меня позвали / не позвали»
data/memory.sqlite3    база (создаётся сама)
```

## Как добавить свой инструмент

В `agent/tools.py`:

```python
@tool("weather", "Погода в городе.", city="string", days={"type": "integer", "_required": False})
def _weather(city: str, days: int = 1) -> dict:
    ...
    return {"temp": 21}
```

Модель сама увидит его в схеме и вызовет, когда нужно. Больше нигде ничего менять не надо.

## Как изменить поведение

Правь `agent/system.md` — это промпт. Например:

```md
## Правила
- Отвечай коротко, по-русски.
- Любую сумму денег переводи в рубли.
```

## Команды в чате

| Команда | Что делает |
|---|---|
| `/start` | справка |
| `/reset` | очистить историю диалога |
| `/notes` | показать сохранённые заметки |

## Ответ в чужом диалоге (группы и топики)

Агент умеет жить в группе и отвечать там, где его позвали, а не молчалками на весь чат.

**Три способа позвать:**

1. `@my_agent_bot найди кофейни` — упоминание по юзернейму.
2. Ответить (реплай) на сообщение бота.
3. Написать слово-триггер в начале: «бот, посчитай 2+2» или «спру, что нового?».
   Слова настраиваются в `.env`: `CALL_WORDS=бот,спру,помощник`.

**Что при этом происходит:**

- В группе бот **молчит**, пока его не позвали — обычная переписка его не касается.
- Текст триггера вырезается перед передачей модели: модель видит только саму задачу.
- История в группе ведётся по ключу (чат + топик + пользователь): у каждого собеседника свой диалог, и общий тред не смешивается с личным.
- Заметки принадлежат конкретному человеку: в промпт подмешиваются только заметки того, кто спросил. Чужие личные данные в группе не утекают.
- `/notes` в группе не отвечает — только в личке.

**Как включить:** добавь бота в группу, дай ему право читать сообщения (в группе без этого он их не видит) и, если нужны треды, — права администратора. В форуме-группах не забудь: топик определяет отдельный контекст.

## Куда расти

- **Браузер**: `playwright` + тул для `web_get` — реально управлять страницами.
- **Файлы**: чтение PDF/DOCX и отправка документов в чат.
- **Напоминания**: таблица `jobs` + фоновый таймер в `bot.py`.
- **Голос**: распознавание речи и ответ голосовым сообщением.
- **Локальная модель**: `OPENAI_BASE_URL=http://localhost:11434/v1` — всё работает оффлайн.
- **Несколько агентов**: скопировать папку, поменять `system.md` — получится другой специалист.

## Подводные камни

- Историю диалога хранится в SQLite целиком — при длинных чатах она растёт. В `core.run` есть `history_limit`.
- `eval` в `calc` ограничен набором символов, но для продакшена лучше заменить на `ast.literal_eval` или sympy.
- Модель может ошибаться в инструментах — проверяй результат важных действий.
